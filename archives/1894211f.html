Linux 文本三剑客之 grep：从入门到精通

一、文本处理与三剑客概述

所有类 Unix 的操作系统都严重依赖文本文件来进行多种类型的数据存储，因此拥有众多文本处理工具是理所当然的。在 Linux 日常运维和软件开发中，文本处理工具无处不在——配置文件、日志分析、源码搜索、数据清洗……几乎每一项任务都离不开对文本的”切分”与”重组”。

在众多文本处理工具中，awk、grep、sed 被合称为 **”文本三剑客”**，是每一个 Linux 用户都必须掌握的核心命令。三者的功能都是处理文本，但侧重点各不相同，其中属 awk 功能最强大，但也最复杂。

grep 更适合单纯的查找或匹配文本；
sed 更适合编辑匹配到的文本；
awk 更适合对结构化文本做字段级分析。

工具 核心能力 典型场景 复杂度
grep 按模式搜索并输出匹配行 日志过滤、关键字查找 ⭐ 入门级
sed 对文本流进行替换/删除/插入 批量替换、行编辑 ⭐⭐ 中级
awk 按字段处理结构化文本，支持编程逻辑 报表生成、数据提取 ⭐⭐⭐ 高级

三者各有所长，常常组合使用，构成 Linux 文本处理的”铁三角”。本文聚焦于三剑客中最基础、最常用的 grep，带你从原理到实战全面掌握它。

二、正则表达式基础

grep 的核心能力建立在正则表达式（Regular Expression） 之上。理解正则，是掌握 grep 的前提。

2.1 什么是正则表达式？

正则表达式是一种符号表示法，被用来识别文本模式。在某种程度上，它们与匹配文件和路径名的 shell 通配符比较相似，但其规模更庞大。许多命令行工具和大多数的编程语言都支持正则表达式，以此来帮助解决文本操作问题。

2.2 正则表达式元字符

正则表达式元字符由以下字符组成：

元字符 含义 示例
. 匹配任意单个字符 a.c 匹配 “abc”、”a1c”
^ 锚定行首 ^start 匹配以 “start” 开头的行
$ 锚定行尾 end$ 匹配以 “end” 结尾的行
[] 字符集合，匹配其中任意一个 [abc] 匹配 “a”、”b” 或 “c”
[^] 排除型字符集合 [^0-9] 匹配非数字字符
- 在 [] 中表示字符范围 [a-z] 匹配任意小写字母
* 前一个字符出现 0 次或多次 ab*c 匹配 “ac”、”abc”、”abbc”
? 前一个字符出现 0 次或 1 次（ERE） ab?c 匹配 “ac” 或 “abc”
+ 前一个字符出现 1 次或多次（ERE） ab+c 匹配 “abc”、”abbc”
() 分组，将多个字符视为一个整体 (ab)+ 匹配 “ab”、”abab”
| 或运算（ERE） cat|dog 匹配 “cat” 或 “dog”
\ 转义字符，使元字符失去特殊含义 \. 匹配字面量的点号

BRE vs ERE：grep 默认使用基本正则表达式（BRE），此时 ?、+、()、{}、| 需要用反斜杠转义（如 \+、\|）。使用 grep -E 或 egrep 则启用扩展正则表达式（ERE），无需转义。

2.3 POSIX 字符类

除了上述元字符，POSIX 标准还定义了一组可读性更好的字符类：

字符类 含义
[:upper:] 大写字母
[:lower:] 小写字母
[:digit:] 数字
[:alpha:] 字母
[:alnum:] 字母和数字
[:space:] 空白字符（空格、制表符等）
[:punct:] 标点符号

注意：在 C/POSIX locale 下 [:digit:] 等价于 [0-9]，但在某些 Unicode locale 下 [:digit:] 会匹配更多数字字符（如全角数字），严格来说两者并不完全等价。跨 locale 编程时建议优先使用 [0-9]。

使用示例：[[:digit:]]\{3\} 匹配三个连续数字（BRE 写法）。

三、grep 引言与历史

3.1 grep 是什么？

grep 是一个最初用于 Unix 操作系统的命令行工具。在给出文件列表或标准输入后，grep 会对匹配一个或多个正则表达式的文本进行搜索，并只输出匹配（或者不匹配）的行或文本。

3.2 grep 的名字由来

grep 这个应用程序最早由肯·汤普逊（Ken Thompson） 写成，他是 Unix 操作系统的联合创始人之一。grep 原先是 ed 编辑器下的一个应用程序，名称来自于 g/re/p——即 globally search a regular expression and print（以正则表达式进行全局查找并打印）。在 ed 下，输入 g/re/p 这个命令后，会将所有符合指定样式的字符串以行为单位打印出来。

1973 年，在 Unix 第四版中，grep 首次出现在 man 手册页面中，从此成为 Unix/Linux 世界最经久不衰的命令之一。

3.3 grep 家族

grep 实用程序是一个大家族，存在许多修改版：

变体 全称 特点
grep Global Regular Expression Print 基础版本，支持 BRE
egrep Extended grep 支持扩展正则表达式（ERE），等价于 grep -E
fgrep Fixed grep 不支持正则，按字面量匹配，速度最快，等价于 grep -F
agrep Approximate grep 支持模糊字符串搜索（近似匹配）
rg (ripgrep) — 现代替代品，支持多线程，速度极快
ag (the silver searcher) — 专为代码搜索优化

所有 grep 的修改版都被应用到很多不同的操作系统中，形成了庞大的 grep 生态。

四、grep 的作用

Linux grep 命令用于查找文件里符合条件的字符串。

换句话说，grep 命令在给定文件中搜索包含与给定字符串或单词匹配的行。对于开发人员和系统管理员来说，它是 Linux 和类 Unix 系统上最有用的命令之一。

典型应用场景：

  • 🔍 日志分析：从海量日志中快速定位错误关键字
  • 📄 代码搜索：在项目中查找某个函数/变量的所有引用
  • 🔒 安全审计：检查配置文件中的敏感信息
  • 📊 数据提取：从结构化文本中提取符合条件的行
  • 🔗 管道协作：与 ps、netstat、ls 等命令配合，实现强大的过滤能力

工作原理：grep 指令用于查找内容包含指定的范本样式的文件。如果发现某文件的内容符合所指定的范本样式，预设 grep 指令会把含有范本样式的那一列显示出来。若不指定任何文件名称，或是所给予的文件名为 -，则 grep 指令会从标准输入设备读取数据。

六、grep 常见选项详解

grep 的选项非常丰富，按功能可分为以下几组：

6.1 匹配控制选项

选项 说明
-i, --ignore-case 忽略字符大小写
-v, --invert-match 反向匹配，显示不被 pattern 匹配到的行
-w, --word-regexp 匹配整个单词（不匹配单词的一部分）
-x, --line-regexp 整行完全匹配
-F, --fixed-strings 将 PATTERN 视为固定字符串（不支持正则），等价于 fgrep
-E, --extended-regexp 使用扩展正则表达式（ERE），等价于 egrep
-G, --basic-regexp 使用基本正则表达式（BRE），默认选项
-P, --perl-regexp 使用 Perl 兼容正则表达式（PCRE），功能最强

6.2 输出控制选项

选项 说明
-c, --count 统计匹配的行数（不显示匹配内容）
-n, --line-number 显示匹配行的行号
-o, --only-matching 仅显示匹配到的字符串（而非整行）
-q, --quiet, --silent 静默模式，不输出任何信息（仅通过退出码判断）
-l, --files-with-matches 只打印包含匹配项的文件名
-L, --files-without-match 只打印不包含匹配项的文件名
-h, --no-filename 多文件搜索时不输出文件名
--color=auto 对匹配到的文本着色显示（高亮）

6.3 上下文控制选项

选项 说明
-A NUM, --after-context=NUM 显示匹配行及其后 NUM 行
-B NUM, --before-context=NUM 显示匹配行及其前 NUM 行
-C NUM, --context=NUM 显示匹配行及其前后各 NUM 行

6.4 文件与目录选项

选项 说明
-r, -R, --recursive 递归搜索目录中的文件
--include=GLOB 只搜索匹配 GLOB 模式的文件
--exclude=GLOB 排除匹配 GLOB 模式的文件
--exclude-dir=GLOB 排除匹配 GLOB 模式的目录
-f FILE, --file=FILE 从文件中读取多个 pattern（每行一个）
-e PATTERN 指定多个 pattern（逻辑 OR 关系）
-m NUM, --max-count=NUM 匹配 NUM 次后停止搜索

跨平台注意：--include、--exclude、--exclude-dir 等选项为 GNU grep 扩展，macOS 自带的 BSD grep 不支持。跨平台使用时建议安装 GNU grep（brew install grep），或使用 find 配合管道。

十、小结

grep 是 Linux 文本处理三剑客中最基础、最高频的命令。它的设计哲学是做好一件事——按模式过滤文本行，并且做到极致。回顾本文要点：

  1. 正则表达式是 grep 的灵魂——掌握元字符、字符类、锚点、分组，就掌握了 grep 的核心武器；
  2. 三剑客各有所长——grep 负责搜索过滤，sed 负责编辑替换，awk 负责字段分析，三者组合威力无穷；
  3. 选项虽多，分类记忆即可——匹配控制、输出控制、上下文、文件处理四大类，各取所需；
  4. 实战中 grep 很少单打独斗——与 sort、uniq、cut、awk、sed 等工具通过管道组合，才能发挥最大威力；
  5. 性能意识很重要——大文件用 -F、-q、-m，超大项目考虑 ripgrep 等现代替代品。

正如《The Linux Command Line》中所强调的：文本处理工具构成了解决实际问题的基础工具集，在后续学习 shell 脚本编程时，这些工具将真正体现出它们的价值。而 grep，就是你踏上这条路的第一块基石。
