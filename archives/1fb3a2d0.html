2. 模型蒸馏

2.1 蒸馏的背景与动机

生产中的实际问题： 每条请求都先过一遍大模型，只为了”读懂问题”还没开始”回答问题”，成本就花了一半。

解决方案： 让小模型来做理解分类等工作。小模型推理成本低、速度快，但直接拿来用效果差——JSON格式经常崩坏，多意图识别不准。蒸馏就是解决这个问题：把大模型的判断能力”复制”给小模型。

2.2 蒸馏的核心概念

定义： 将大模型（Teacher模型）的能力迁移到小模型（Student模型）的过程。

核心思想： 让Student模型学习Teacher模型的行为表现，而非仅仅学习原始数据。

蒸馏 vs 微调：

对比项 普通监督微调 SFT 大模型蒸馏
数据来源 人工标注、业务数据 Teacher模型生成的问答、解释、推理
学习目标 学习标准答案 学习Teacher的能力、风格、判断路径
典型形式 instruction → answer instruction → teacher answer / rationale
成本 人工标注成本高 调用Teacher成本高，但标注成本低
风险 数据质量不足 Teacher错误、幻觉、偏见会被复制
适合场景 任务边界明确 想迁移复杂能力或快速构造训练集

2.3 蒸馏的主要技术路线

路线一：答案蒸馏（Response Distillation）

蒸馏数据格式示例：

优点： 最简单、最容易落地
缺点： 只学最终答案，小模型可能只学到”说话样子”，没有真正学会推理

路线二：推理过程蒸馏（Rationale / CoT Distillation）

不只让Teacher给答案，还让Teacher给出解释、判断依据、推理步骤。

优点： 小模型学到的是”思考过程”，泛化能力更强
代表研究： Google “Distilling step-by-step” — 利用大模型生成的rationales作为额外监督，让小模型用更少数据取得更好表现

路线三：数据合成蒸馏

用Teacher模型生成大量训练数据，清洗后用于训练Student模型。

流程：

典型应用： DistilQwen2.5-R1系列 — 以少量DeepSeek-R1的思维链蒸馏数据为基础，强化小模型深度思考能力。

2.4 蒸馏的适用场景

适用场景 说明
垂直行业问答 把强模型在特定领域的知识迁移到小模型
结构化信息抽取 固定格式输出（JSON、表格等）
固定格式报告生成 模板化内容生成
意图识别/分类 先理解再回答，降低链路成本

2.5 蒸馏实战要点

Qwen Code辅助蒸馏流程：

  1. 准备蒸馏数据集（问题 + Teacher模型的输出）
  2. 使用Qwen Code生成训练脚本
  3. 在PAI平台进行训练
  4. 评测Student模型效果
  5. 部署Student模型

注意事项：

  • Teacher模型的选择直接影响Student模型上限
  • 蒸馏数据质量比数量更重要
  • 需要定期用Teacher模型更新蒸馏数据

3. 模型部署

3.1 部署方式对比

部署方式 说明 优点 缺点 适用场景
直接调用API 调用阿里云百炼等预置模型API 无需部署、按量计费、无需运维 成本随调用量线性增长 业务初期、中小规模
PAI平台部署 在阿里云PAI上部署模型 零代码部署、一键推理、弹性扩缩容 需绑定阿里云平台 中大规模、需GPU资源
私有化部署 自建GPU服务器部署 数据完全本地、无网络延迟 运维成本高、硬件投入大 数据安全要求高

3.2 直接调用API

适合场景： 业务初期或中小规模场景

优势：

  • 直接调用，无需部署模型
  • 按Token量计费，无需担心GPU资源消耗
  • 自动扩缩容、模型版本升级等运维工作由服务商完成

3.3 PAI平台部署阿里云

PAI-ModelGallery核心能力：

能力 说明
模型部署 支持BladeLLM、VLLM、Transformers标准部署等多种部署方式
零代码部署 预置部署配置信息，一键部署
API兼容 支持OpenAI API兼容方式调用
WebUI交互 支持ChatLLM WebUI实时交互

PAI平台支持的部署方式：

  • BladeLLM部署：高性能推理引擎
  • VLLM部署：高吞吐量推理
  • Transformers标准部署：标准HuggingFace部署方式

3.4 推理优化技术

技术 说明 效果
模型量化 INT8/INT4量化（GPTQ/AWQ） 显存降低50-75%，速度提升2-4倍
KV Cache 缓存已计算的Key-Value 减少重复计算，加速推理
投机解码 用小模型生成候选，大模型验证 加速推理1.5-2倍
批处理（Batching） 合并多个请求同时推理 提高GPU利用率
上下文缓存 缓存高频重复查询结果 降低调用开销

3.5 部署选型策略

根据需求选择部署方式：

需求 推荐方案
快速验证、低成本启动 直接调用API（百炼平台）
中大规模生产、需要定制 PAI平台部署（BladeLLM/VLLM）
数据安全要求极高 私有化部署（自建GPU集群）
需要极致推理性能 量化 + 批处理 + KV Cache优化

4. 大模型应用生产实践

4.1 业务需求分析

业务需求分析是大模型部署成功的第一步，不同业务场景对模型的功能性和非功能性需求差异大。业务场景不清晰可能导致模型选择错误、用户体验下降、成本失控、安全隐患等问题。

应对策略： 明确业务场景后，围绕功能性和非功能性需求深入分析，制定具体部署方案。

4.2 模型功能性需求

任务类型 推荐模型
通用语言任务 通用大语言模型（Qwen-Plus等）
特定领域任务（数学、法务、医疗） 领域微调模型（Qwen-Math等）
视觉任务 专门视觉模型（通义万相、Stable Diffusion）
语音任务 专门语音模型（Qwen-Audio、CosyVoice）
多模态任务 多模态模型（Qwen-VL）

模型评估方法： 构建评测数据集或选择公开数据集进行评测，如MMLU评估语言理解、BBH测试复杂推理等。

4.3 模型非功能性需求

维度 说明 关键指标
性能 响应速度要求 TTFT（首Token延迟）、TPOT（每个Token生成时间）
成本 模型推理和硬件资源成本 GPU实例规格、计费方式
稳定 系统提供稳定可靠的服务 SLA、可用性、容灾
安全 数据隐私、内容安全合规 安全护栏、数据加密

4.4 性能优化策略

系统性能提升

策略 说明
选择小模型 通过模型压缩（量化、剪枝、蒸馏）加速推理
上下文缓存 缓存高频重复查询结果
批处理 合并或去除重复请求
减少Token数量 精简输入、指定输出最大长度
并行化处理 数据并行、模型并行、流水线并行
不要默认依赖大模型 标准化输出用硬编码，预先计算复用内容

用户感知优化

策略 说明
流式输出 逐步返回生成内容，减少用户感知延迟
分块处理 将任务分解为多个小块分别处理
展示任务进度 让用户了解系统处理状态
完善错误处理 分类错误、友好提示、重试机制、降级方案
用户反馈入口 鼓励反馈，持续改进

4.5 成本优化方案

策略 说明
用小模型替换大模型 推理更快且成本更低
上下文缓存 缓存高频重复查询结果
批量推理 合并或去重请求，利用空闲资源
减少Token数量 精简输入输出
避免大模型处理所有任务 硬编码、预先计算替代

云上部署成本优化：

  • 选择合适的GPU实例规格：根据模型参数量、KV Cache占用、精度设置选择
  • 选择合适的计费方式：预付费（包年包月）、按量付费、抢占式实例

4.6 稳定性保障

措施 说明
降低请求资源消耗 优化Prompt长度、模型量化
自动化扩缩容 根据负载自动调整实例数量
评测基线管理 建立基线，每次更新后验证效果
实时监控与预警 监控关键指标，设置告警阈值
容灾性设计 多可用区部署、主备切换

4.7 可观测性

可观测性是大模型应用生产实践的必备能力，覆盖三大支柱：

支柱 说明 大模型场景关注点
Trace（链路追踪） 追踪请求的完整链路 从用户输入到模型输出的完整路径
Log（日志） 记录系统运行日志 输入输出日志、异常日志
Metric（指标） 量化监控指标 Token消耗、延迟、QPS、错误率

核心监控指标（必背）：

指标 说明
QPS（每秒查询数） 系统吞吐量
TTFT（首Token延迟） 用户感知的第一响应时间
TPOT（每个Token生成时间） 生成速度
Token消耗量 成本控制核心指标
错误率 请求失败比例
模型准确率 回答正确率

5. 大模型应用安全合规

5.1 安全威胁类型

攻击类型一：提示词注入攻击

用户通过精心设计的提示词诱导模型绕过安全限制，获取未经授权的信息。

典型攻击示例：

攻击原理： 诱导模型进行角色扮演，从而绕过安全限制。

攻击类型二：越权访问

用户试图获取超越自身权限的信息。

攻击类型三：多模态内容安全

图片、音频等多媒体内容中可能包含违规信息。

5.2 阿里云AI安全护栏

阿里云提供多层安全防护机制：

安全层 防护内容 说明
输入安全 输入内容审核 过滤恶意提示词、敏感信息
输出安全 输出内容审核 检查模型输出是否合规
内容安全检测 多模态内容审核 图片、文本、音频安全检测

5.3 数据安全与隐私保护

合规第一原则： 大模型应用必须遵守法律法规，确保数据安全和隐私保护。

数据安全红线：

  • 涉密/业务/客户数据必须脱敏+加密
  • 禁止明文密钥、密码、内网IP、配置文件传入大模型
  • 核心私有业务数据，禁止上传公有云通用大模型
  • 优先：私有化部署模型 + 本地向量库 + 内网闭环

权限管控：

  • 遵循RBAC最小权限原则
  • 角色分级、访问鉴权、操作隔离
  • 禁止匿名访问、公开接口暴露

审计与追溯：

  • 全链路日志留存：提问、推理过程、检索记录、工具调用
  • 确保可追溯、可审计

5.4 纵深防御策略

体系化AI安全纵深防御：

层级 防护措施
输入层 输入内容过滤、提示词注入检测
应用层 身份认证、权限校验、操作审计
模型层 模型安全对齐、安全护栏、内容安全检测
输出层 输出内容审核、敏感信息过滤
基础设施层 网络安全、数据加密、访问控制

5.5 内容安全实践

内容安全检测维度：

  • 涉政内容检测
  • 涉黄内容检测
  • 涉暴内容检测
  • 广告违规检测
  • 敏感信息检测

阿里云内容安全产品： 提供文本、图片、音频、视频等多模态内容安全检测服务。
