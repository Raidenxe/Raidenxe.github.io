1. Helm 简介

Helm 是 Kubernetes 的包管理工具，类似于 Linux 中的 apt 或 yum。它通过 Chart（图表）的方式将 Kubernetes 资源打包、版本化管理，实现一键部署、升级和回滚。

1.1 核心概念

概念 说明
Chart Helm 的软件包，包含部署应用所需的所有 Kubernetes 资源模板
Release Chart 在集群中的一次运行实例，同一个 Chart 可以部署多次
Repository Chart 的存储仓库，可以公开或私有
Values 配置值，覆盖 Chart 中的默认参数

1.2 Helm v3 架构变化

Helm v3 移除了 v2 中的 Tiller 服务端组件，改为直接通过 kubeconfig 与 Kubernetes API Server 通信：

这一变化带来了以下改进：

  • 去除了单点故障（Tiller 崩溃影响所有 Release）
  • 安全性提升（无需在集群内运行特权组件）
  • 支持多命名空间隔离（不同用户使用不同 kubeconfig）
  • 不再需要 helm init 初始化

3. 使用 Helm 安装 CNI 插件

CNI（Container Network Interface）插件是 Kubernetes 集群网络的核心组件。使用 Helm 安装 CNI 插件可以简化部署流程，便于版本管理和配置更新。

3.1 安装 Calico（推荐）

Calico 是 Kubernetes 生态中最流行的 CNI 插件之一，支持网络策略、BGP 路由、VXLAN 封装等特性。

3.2 安装 Flannel

Flannel 是轻量级的 CNI 插件，使用 VXLAN 或 host-gw 模式实现跨节点通信。

3.3 安装 Cilium

Cilium 是基于 eBPF 的新一代 CNI 插件，提供高性能网络和安全能力。

3.4 CNI 插件选择对比

插件 特点 网络策略 性能 适用场景
Calico 功能全面，支持 BGP/VXLAN 完整支持 高 生产环境首选
Flannel 轻量，配置简单 不支持 中 测试/开发环境
Cilium eBPF 驱动，可替代 kube-proxy 完整支持（L3-L7） 极高 高性能/安全敏感场景
Weave 多跳网络，加密传输 部分支持 中 跨云/混合环境

4. Helm 常用命令总结

4.1 仓库管理

命令 说明
helm repo add <name> <url> 添加 Chart 仓库
helm repo list 列出所有仓库
helm repo update 更新仓库索引
helm repo remove <name> 移除仓库

4.2 Chart 搜索与查看

命令 说明
helm search repo <keyword> 搜索仓库中的 Chart
helm search hub <keyword> 搜索 Helm Hub 中的 Chart
helm show chart <repo>/<name> 查看 Chart 元信息
helm show values <repo>/<name> 查看 Chart 默认配置值
helm show readme <repo>/<name> 查看 Chart 说明文档
helm show all <repo>/<name> 查看 Chart 所有信息

4.3 Chart 安装与部署

命令 说明
helm install <name> <chart> 安装 Chart
helm install <name> <chart> --namespace <ns> 指定命名空间安装
helm install <name> <chart> -f values.yaml 使用自定义 values 文件安装
helm install <name> <chart> --set key=value 命令行设置参数
helm install <name> <chart> --dry-run --debug 预览安装结果（不实际执行）

4.4 Release 管理

命令 说明
helm list 列出所有 Release
helm list -n <namespace> 查看指定命名空间的 Release
helm list --all-namespaces 查看所有命名空间的 Release
helm status <release> 查看 Release 状态
helm history <release> 查看 Release 版本历史
helm get values <release> 查看 Release 的配置值
helm get manifest <release> 查看 Release 生成的 YAML 清单

4.5 升级与回滚

命令 说明
helm upgrade <release> <chart> 升级 Release
helm upgrade <release> <chart> -f new-values.yaml 使用新配置升级
helm upgrade <release> <chart> --set image.tag=latest 升级镜像版本
helm upgrade --install <release> <chart> 安装或升级（不存在则安装）
helm rollback <release> <revision> 回滚到指定版本
helm rollback <release> 0 回滚到上一个版本

4.6 Chart 打包与发布

命令 说明
helm create <chart-name> 创建 Chart 模板
helm lint <chart-path> 检查 Chart 语法
helm package <chart-path> 打包 Chart 为 .tgz 文件
helm template <name> <chart> 本地渲染模板（不部署）
helm push <chart> <repo> 推送 Chart 到仓库（OCI）
helm pull <repo>/<name> 拉取 Chart 包到本地

4.7 卸载与清理

命令 说明
helm uninstall <release> 卸载 Release
helm uninstall <release> --keep-history 卸载但保留历史记录
helm repo remove <name> 移除仓库
helm repo prune 移除不再使用的仓库

5. Helm 使用与安全管理

5.1 Helm 使用最佳实践

版本管理

  • 始终使用 helm upgrade --install 而非直接 helm install，确保幂等性
  • 使用 -f values.yaml 文件管理配置，避免过长的 --set 参数链
  • 按环境拆分 values 文件：values-dev.yaml、values-staging.yaml、values-prod.yaml

Chart 编写规范

  • 使用 helm create 生成标准 Chart 结构
  • 为 values 提供合理的默认值（如 image.tag 不应默认为 latest）
  • 使用 --dry-run 和 helm lint 在部署前验证

依赖管理

  • 使用 Chart.yaml 的 dependencies 字段声明依赖
  • 使用 helm dependency update 更新依赖包

镜像安全

  • 始终使用不可变的镜像摘要（digest），而非可变的标签（tag）
  • 避免使用 latest 标签

  • 为每个 Release 创建独立的 ServiceAccount
  • 限制 Role 的权限范围到最小必要

5.3 安全加固清单

检查项 说明 优先级
使用 helm template 预览渲染结果 部署前审查生成的 YAML 高
禁用 priviledged: true 防止容器逃逸 高
禁用 hostNetwork 防止直接访问宿主机网络 高
避免 image:latest 标签 使用不可变摘要 高
敏感信息使用 Secret 引用 禁止明文存储 高
设置 runAsNonRoot: true 非 root 用户运行 高
限制 capabilities 最小化内核能力 中
设置 readOnlyRootFilesystem: true 只读根文件系统 中
配置 NetworkPolicy 网络隔离 中
使用 Chart 签名与验证 供应链安全 中
使用 values.schema.json 配置值校验 低
定期扫描 Chart 依赖项 CVE 漏洞管理 低

5.4 常见问题排查

问题 原因 解决
helm install 报 already exists Release 名称冲突 使用 helm upgrade --install
helm list 不显示已安装的 Release 命名空间不对 检查 -n 参数或使用 --all-namespaces
helm install 卡住 镜像拉取失败 检查 kubectl describe pod 的 Events
升级后 Pod 未更新 imagePullPolicy 为 IfNotPresent 修改镜像标签或设置 pullPolicy: Always
helm repo update 慢 网络问题 使用国内镜像仓库

总结

Helm 是 Kubernetes 生态中不可或缺的包管理工具，从简单的应用到复杂的 CNI 插件，都可以通过 Helm 实现标准化部署。使用 Helm 安装 CNI 插件（如 Calico）可以大幅简化集群网络配置过程，同时利用 Helm 的版本管理能力实现可控的升级和回滚。

在安全管理方面，核心原则是：部署前渲染审查、敏感信息外部化、镜像摘要锁定、RBAC 最小权限、安全上下文加固。遵循这些最佳实践，可以有效降低生产环境的安全风险。
