七、故障排查与经验总结

7.1 常见问题

问题 原因 解决方案
clone-mysql 阶段 ncat: Could not resolve hostname Flannel 未安装，跨节点 DNS 不可达 安装 Flannel CNI
Slave_IO_Running: Connecting 主从网络不通或 MASTER_HOST 配置错误 检查 clusterDomain 配置，确保 FQDN 正确
PV 一直 Pending 未创建 PV 或 StorageClass 不匹配 手动创建静态 PV，设置 storageClassName: ""
Pod Insufficient memory MySQL 资源请求过高 调整 resources.requests.memory
CoreDNS NotReady Flannel 安装后 CoreDNS 需要重启 kubectl delete pod -n kube-system -l k8s-app=kube-dns

7.2 架构设计要点

  1. StatefulSet 有序部署：Pod 按序号顺序启动，确保 mysql-0 先启动并提供克隆服务
  2. 边车模式（Sidecar）：xtrabackup 作为边车容器与 MySQL 共享数据卷，通过 ncat 提供 xtrabackup 流服务
  3. 链式克隆：mysql-1 从 mysql-0 克隆，mysql-2 从 mysql-1 克隆，减轻主库压力
  4. Headless Service + 只读 Service：分离读写流量，读请求通过 mysql-read 负载均衡
  5. NFS 静态 PV：使用 storageClassName: "" 禁用动态置备，手动绑定 PV

7.3 最佳实践建议

  • 生产环境：建议使用 storageClassName 动态置备，避免手动管理 PV
  • MySQL 版本：MySQL 5.7.39 版本存在已知 bug，建议使用 5.7.36 或 5.7.44
  • 资源限制：Minikube 默认 4GB 内存，3 个 MySQL Pod 各请求 1Gi 内存，需调整资源或增加 VM 内存
  • 网络插件：多节点 Minikube 必须安装 Flannel/Calico 等 CNI 插件，默认 bridge 不支持跨节点通信

九、总结

本文详细记录了在 Minikube 三节点集群上部署 MySQL 主从复制（1 主 2 从）的完整过程，实现了以下核心功能：

功能 实现方式 状态
自动配置 server-id init-mysql 容器根据 Pod 序号生成 ✅
自动数据克隆 clone-mysql 容器通过 xtrabackup + ncat ✅
自动主从复制 xtrabackup 边车容器解析 binlog 位置并执行 CHANGE MASTER TO ✅
读负载均衡 mysql-read Service（ClusterIP） ✅
写操作限制 replica.cnf 的 super-read-only 配置 ✅
数据持久化 NFS 静态 PV ✅
跨节点网络 Flannel vxlan ✅

关键经验：Minikube 多节点环境下，必须安装 Flannel 等 CNI 插件解决跨节点 Pod 通信问题；StatefulSet + Headless Service 是部署有状态应用的黄金组合；边车模式为 MySQL 集群提供了优雅的数据克隆和复制配置方案。
