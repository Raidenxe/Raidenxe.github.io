背景与痛点

Docker 作为云原生时代的核心基础设施，几乎是每位开发者和运维人员的必备工具。然而在国内网络环境下，Docker 的部署和镜像拉取往往面临两大痛点：

  • 痛点一：官方源访问不稳定。Docker 官方下载站 download.docker.com 在国内部分地区访问缓慢甚至无法连接，导致二进制包下载失败。
  • 痛点二：镜像拉取速度极慢。由于网络原因，从 Docker Hub 拉取镜像时经常超时或速度极慢，严重影响开发效率。

传统的解决方案是手动下载二进制包、复制到 /usr/bin、配置 systemd 服务、再手工编辑 daemon.json 添加镜像源——步骤繁琐且容易出错。本文将分享一个一键完成的 Shell 脚本，实现 Docker 二进制部署与镜像加速配置的自动化。

脚本功能概述

该脚本主要实现以下功能：

  • 支持指定版本或自动获取最新版本：可通过命令行参数指定版本号（如 ./install_docker.sh 29.6.0），不传参数则自动从多个镜像源获取最新稳定版。
  • 多源下载容错：依次尝试官方源、阿里云镜像、清华镜像等多个地址下载二进制包。
  • 全自动安装：解压二进制文件、复制到 /usr/bin、创建 docker 用户组、配置 systemd 服务。
  • 镜像加速配置：自动生成 /etc/docker/daemon.json，配置多个国内镜像加速器，同时支持 insecure-registries 私有仓库。
  • 服务验证：安装完成后自动启动 Docker 并验证服务状态。

常见问题与排查

Q1：提示”所有镜像源下载均失败”怎么办？

A：可以手动从可用的镜像源下载对应版本的 docker-<version>.tgz 包，放到 /tmp 目录下，然后修改脚本跳过下载步骤直接解压安装。或者检查网络连通性，确认是否能访问 mirrors.aliyun.com 等域名。

Q2：Docker 启动失败如何排查？

A：使用 journalctl -u docker 查看服务日志，常见原因包括 daemon.json 格式错误（JSON 语法问题）或端口冲突。

Q3：镜像加速未生效？

A：检查 /etc/docker/daemon.json 文件是否存在且格式正确。修改后需要重启 Docker 服务：systemctl restart docker。

Q4：insecure-registries 有什么用？

A：Docker 默认只信任 HTTPS 的镜像仓库。如果企业内部使用 HTTP 协议的 Harbor 等私有仓库，需要将其地址加入 insecure-registries 列表，否则拉取镜像时会报错。

总结

本文介绍了一键完成 Docker 二进制部署与镜像加速配置的 Shell 脚本。该脚本具备以下优势：

  • 全自动：从下载、安装到配置一站式完成，无需手工干预。
  • 高可用：多源容错机制确保在网络不稳定的情况下依然能够成功部署。
  • 可定制：支持指定版本、自定义镜像源和私有仓库配置。
  • 跨平台：自动适配 x86_64、aarch64、armv7l 等主流架构。

通过该脚本，开发者可以在几分钟内完成 Docker 环境的搭建，将精力更多地投入到业务开发中。希望本文对大家有所帮助！
