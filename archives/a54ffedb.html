1. 什么是 JumpServer

JumpServer 是开源的堡垒机/跳板机系统，用于集中管理企业内部服务器的访问权限。它解决了以下核心问题：

问题 JumpServer 解决方案
权限分散 统一认证、细粒度授权管理
操作审计 全程录像、命令审计、操作日志
密钥管理 集中管理 SSH 密钥，避免密钥分散
合规要求 满足等保、SOX 等合规审计需求

JumpServer 采用 B/S 架构，支持 Web 端直接管理和操作服务器，无需安装客户端。核心价值在于：让运维操作可追溯、可审计、可控制。

5. 纳管实验节点

5.1 概念说明

JumpServer 通过**资产(Assets)**管理被纳管的服务器节点。纳管方式分为:

  • SSH 密码登录: 适用于已知密码的服务器
  • SSH 密钥登录: 使用公私钥认证 (推荐)
  • 自动推送: JumpServer 自动将系统用户推送到目标资产

5.2 纳管流程

步骤 1: 创建资产 (被纳管节点)

Web UI: 控制台 → 资产管理 → 资产列表 → 创建资产

字段 说明 示例值
主机名 资产名称标识 node-1
IP 地址 目标节点 IP 192.168.x.x
协议 管理协议 SSH
端口 SSH 端口 22
系统平台 操作系统 Linux

步骤 2: 创建系统用户

Web UI: 控制台 → 资产管理 → 系统用户 → 创建系统用户

系统用户是目标资产上的真实用户，JumpServer 使用该用户登录目标资产。

字段 说明 示例值
名称 用户标识 root
用户名 目标资产上的用户名 root
认证方式 密码 / 密钥 / 自动推送 密钥
自动推送 是否自动将用户推送到资产 勾选

步骤 3: 授权用户

Web UI: 控制台 → 权限管理 → 资产授权 → 创建授权

字段 说明
名称 授权规则名称
用户 选择要授权的 JumpServer 用户
资产 选择要授权的目标资产
系统用户 选择使用的系统用户
权限 全部权限 / 连接 / 上传下载 / 等

5.3 实验节点纳管示例

假设要纳管一台 Linux 节点 192.168.x.x (root 密码已知):

方式一: 密码认证

  1. 创建资产: 主机名=node-1, IP=192.168.x.x, 协议=SSH
  2. 创建系统用户: 名称=root-ssh, 用户名=root, 认证方式=密码
  3. 在系统用户详情中设置密码
  4. 创建授权: 选择该用户和资产
  5. 在 Web 终端连接测试

方式二: 密钥认证 (推荐)

方式三: 自动推送 (最便捷)

  1. 创建资产: 主机名=node-1, IP=192.168.x.x
  2. 创建系统用户: 勾选 自动推送, 设置用户名(如 jmsadmin)和密码
  3. JumpServer 会自动 SSH 到目标节点创建该用户并设置 sudo 权限
  4. 创建授权规则即可连接

5.4 连接测试

  • Web UI: 进入 工作台 → Web 终端，选择目标资产
  • 命令: ssh -p 2222 <用户名>@<your-server-ip> (需配置)

6. 组件架构与作用

6.1 架构概览

JumpServer 采用单体部署架构（jms_all 镜像），将所有核心组件打包在一个容器中，便于快速部署和管理。

6.2 组件详解

组件 服务名 端口 作用
Core core 8080 核心后端 API，处理认证、授权、资产管理、审计日志等所有业务逻辑
Koko koko 2222 SSH/Telnet 字符协议代理，负责 SSH 连接转发、会话录制
Lion lion 8081 VNC 图形协议代理，支持通过 Web 访问 VNC 协议的资产
Razor razor 3389 RDP 协议代理，支持 Windows 远程桌面连接
Chen chen 8083 数据库代理，支持 MySQL、PostgreSQL 等数据库的 Web 连接
Kael kael 8085 应用发布代理，支持发布 Chrome、SQL 工具等应用程序
Web web 80 Nginx 前端代理，统一入口，反向代理到各组件
Celery celery - 异步任务队列，处理录像处理、资产推送、邮件通知等后台任务
Magnus magnus - 数据库隧道代理，支持通过 Navicat 等客户端直连数据库

7.2 docker-compose.yml 关键配置说明

配置项 说明
privileged: true 特权模式，JumpServer 需要在容器内创建和管理 Docker 容器
depends_on.condition: service_healthy 等待依赖服务健康后才启动，确保启动顺序
healthcheck 容器健康检查，Docker 根据返回值判断服务是否正常
volumes 数据持久化挂载，将容器内数据映射到宿主机
networks.ipam.config.subnet 指定容器子网，避免与宿主机网络冲突
