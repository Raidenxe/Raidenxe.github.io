一、概述

kube-prometheus-stack 是 Prometheus 社区维护的一体化监控栈 Helm Chart，包含以下核心组件：

组件 作用
Prometheus 时序数据库 + 指标采集与存储
Alertmanager 告警接收、分组、去重、路由与通知
Grafana 可视化面板（内置丰富 dashboard）
Node Exporter 节点级主机指标（CPU/内存/磁盘/网络），DaemonSet 方式运行
kube-state-metrics Kubernetes 对象状态指标（Pod/Deployment/Node 等）
cAdvisor（集成于 kubelet） 容器级资源指标采集（CPU/内存/网络/文件系统/CFS 节流）。无需独立部署，由 kubelet 的 /metrics/cadvisor 端点暴露，kube-prometheus-stack 通过 serviceMonitor/monitor/kube-prometheus-stack-kubelet/0 自动抓取
Prometheus Operator 用 CRD 管理 Prometheus/Alertmanager 实例

cAdvisor 与 kube-state-metrics 的区别（新手常混淆）

对比项 cAdvisor kube-state-metrics
数据来源 cgroup（内核层面） Kubernetes API Server
关注点 容器运行时的资源使用 K8s 对象的状态
典型指标 container_cpu_usage_seconds_total kube_pod_status_phase
回答的问题 “容器用了多少资源？” “K8s 对象现在是什么状态？”

💡 两者互补，不能互相替代。

四之二、外部网络访问（局域网其他机器）

方案说明

minikube 节点 IP（如 <MINIKUBE_NODE_IP_1>）属于宿主机内部 NAT 网络，局域网其他机器无法直达。通过在宿主机上运行 kubectl port-forward --address=0.0.0.0，把监控服务监听到宿主机的局域网 IP <HOST_LAN_IP>，外部网络即可访问。

这是整个 port-forward 方案中唯一需要 root 的一次性操作。开启后，即使不登录，隧道服务也会在开机时自动启动。若不开启 linger，则隧道仅在用户登录期间运行。

注意事项

  • port-forward 通过 apiserver 建立隧道，Pod 重启时连接会短暂中断，Restart=always 会自动重连（约 5 秒）。
  • 该方案适合中小规模访问；若需高并发或生产级，建议改用 iptables DNAT 或 Ingress（见四之三节）。
  • 监听 0.0.0.0 意味着局域网所有机器均可访问 Grafana（admin/admin），请确认网络环境安全，或修改密码。

5.2 cAdvisor（容器顾问）详解

cAdvisor 是什么

cAdvisor（Container Advisor）是 Google 开源的容器资源采集器，集成在 kubelet 二进制中。所有 cAdvisor 指标都以 container_ 为前缀，并自带 pod、namespace、container、image 等标签，方便与 Kubernetes 对象关联。

💡 重要认知：很多人误以为 cAdvisor 是一个需要单独跑的 DaemonSet。实际上在 Kubernetes 集群中，kubelet 已经内置了 cAdvisor，所有 container_* 前缀的指标都来自这里。只有在裸 Docker 环境才需要独立部署 cAdvisor 容器。

cAdvisor 提供的核心指标类别

类别 典型指标 含义
CPU container_cpu_usage_seconds_total CPU 累计使用时间（核·秒）
container_cpu_cfs_throttled_seconds_total 因 CFS 带宽限制被节流的时间
container_cpu_system_seconds_total 内核态 CPU 时间
container_cpu_user_seconds_total 用户态 CPU 时间
内存 container_memory_working_set_bytes 工作集内存（OOM 判断依据）
container_memory_usage_bytes 总内存用量（RSS + Cache）
container_memory_rss 匿名内存和栈内存
container_memory_cache 页面缓存
磁盘 I/O container_fs_reads_bytes_total 磁盘读字节累计
container_fs_writes_bytes_total 磁盘写字节累计
container_fs_usage_bytes 容器根文件系统使用量
container_fs_limit_bytes 容器根文件系统容量上限
网络 container_network_receive_bytes_total 网络收字节累计
container_network_transmit_bytes_total 网络发字节累计
container_network_receive_errors_total 网络收错误包数
container_network_transmit_errors_total 网络发错误包数
生命周期 container_start_time_seconds 容器启动时间戳
container_last_seen 最后一次被 cAdvisor 看到的时间
压力指标 container_pressure_cpu_seconds_total CPU 压力等待时间（PSI）
container_pressure_memory_total 内存压力累计（PSI）

⚠️ 注意区分：宿主机磁盘、Inode 等节点级指标由 node-exporter 提供；cAdvisor 只反映容器视角。两者互补，不能互相替代。

默认 Alertmanager 不发送外部通知（仅 Web UI 可见）。接入钉钉/企业微信需先理解一个关键点：

⚠️ 重要：不能把钉钉/企微机器人 URL 直接填到 webhook_configs。
Alertmanager 的 webhook 发出的是固定 v4 格式 JSON（{"version":"4","alerts":[...]}），而钉钉/企微机器人只接受各自的消息格式（{"msgtype":"markdown","markdown":{...}}），格式不兼容，直连会被机器人拒绝（返回 errcode）。必须中间加一层转发器做格式转换。

8.3 cAdvisor 指标缺失（Target Up 但查不到 container_* 指标）

现象：serviceMonitor/monitor/kube-prometheus-stack-kubelet/0 状态为 Up，但 PromQL 查 container_cpu_usage_seconds_total 无数据。

  1. 确认端点路径正确：cAdvisor 指标在 /metrics/cadvisor，不在 /metrics。/metrics 只有 kubelet 自身指标。

  3. 检查 kubelet 是否集成 cAdvisor：minikube 默认集成。
