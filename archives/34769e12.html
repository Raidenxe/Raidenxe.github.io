KVM 虚拟化从入门到实践：架构、部署与网络管理

1 虚拟化基础

虚拟化是通过软件技术将物理资源（CPU、内存、存储、网络）抽象成逻辑资源，实现单台物理机运行多个隔离的**”虚拟机”**的技术。主要类型：

  • 全虚拟化：模拟完整硬件环境，无需修改客户机操作系统（如 KVM、VMware ESXi）
  • 半虚拟化：客户机需修改内核，通过特定接口访问硬件，性能接近物理机（如 Xen 的 PV 模式）
  • 容器化：操作系统级虚拟化，共享宿主机内核（如 Docker）

KVM（Kernel-based Virtual Machine）是 Linux 内核模块，将 Linux 转变为类型 1（裸金属）虚拟机监控器（Hypervisor），依赖硬件虚拟化技术（Intel VT-x / AMD SVM）。

2 KVM架构与核心组件

KVM 技术栈由三个层次分明的组件构成：KVM（内核态）、QEMU（用户态） 和 libvirt（管理层）。理解三者的关系，是掌握 KVM 虚拟化的关键。

2.1 KVM 内核模块

KVM 由内核模块 kvm.ko + 处理器特定模块（kvm_intel.ko 或 kvm_amd.ko）组成。kvm.ko 提供核心虚拟化框架，处理器相关模块负责初始化 CPU 硬件虚拟化功能。

KVM 的职责：

  • CPU 虚拟化：利用 VT-x/AMD-V 让 vCPU 指令直接在物理 CPU 上执行，无需软件翻译
  • 内存虚拟化：通过 EPT（Intel）或 NPT（AMD）实现虚拟地址到物理地址的转换
  • vCPU 调度：将每个虚拟 CPU 作为 Linux 线程调度

KVM 不模拟任何 I/O 设备——它不知道什么是硬盘、什么是网卡。它通过 /dev/kvm 设备文件向外暴露内核虚拟化能力，用户态程序通过 ioctl 系统调用与 KVM 交互。

2.2 QEMU：设备模拟器

QEMU（Quick Emulator）是一个开源的机器模拟器。在 KVM 架构中，QEMU 作为用户态组件运行，承担以下职责：

  • 设备模拟：模拟磁盘（virtio-blk、IDE、SATA）、网卡（virtio-net、e1000）、USB、显卡、串口等
  • 虚拟机进程管理：每个虚拟机对应一个 QEMU 进程，虚拟机中的每个 vCPU 对应 QEMU 进程中的一个线程
  • 与 KVM 通信：通过 /dev/kvm 的 ioctl 接口，将 vCPU 交给 KVM 执行，并在 I/O 发生时接收控制权

QEMU 可以独立于 KVM 运行（纯软件模拟），但性能很低。有了 KVM 加速后，CPU 指令直接运行，只有 I/O 操作才经过 QEMU 模拟，这是 KVM-QEMU 组合高性能的根本原因。

2.3 libvirt：管理接口层

libvirt是一套开源的虚拟化管理 API 和工具集，它独立于具体的 hypervisor，支持 KVM、Xen、LXC、VMware ESXi 等多种后端。

libvirt 的职责：

  • 统一管理接口：提供 virsh（命令行）和 virt-manager（图形界面）等工具
  • 配置标准化：用 XML 文件定义虚拟机的 CPU、内存、磁盘、网络等配置
  • 生命周期管理：虚拟机的创建、启动、暂停、迁移、删除
  • 资源管理：存储池管理、虚拟网络管理（NAT、桥接、隔离网络）

libvirt 是唯一与 QEMU/KVM 直接交互的组件。用户通过 virsh 或 virt-manager 发出请求，libvirtd 将请求转换为 QEMU 命令行参数或 QEMU Monitor 命令，最终由 QEMU 和 KVM 执行。

2.4 三组件协作全流程

一句话概括三者的关系：

组件 一句话概括
KVM 让 CPU 和内存”跑得快”（硬件加速）
QEMU 让各种外设”长得像”（设备模拟）
libvirt 让所有操作”管得住”（统一管理接口）

数据流示例：虚拟机发起一次磁盘写入

  1. 虚拟机中的应用程序调用 write() 系统调用
  2. 虚拟机内核将数据写入 virtio-blk 前端驱动
  3. virtio 驱动通过 virtqueue 将请求传递给 QEMU 的用户态后端
  4. QEMU 接收到 I/O 请求，将数据写入宿主机上的磁盘文件（如 qcow2）

整个过程中，KVM 负责在 vCPU 退出时将控制权交给 QEMU，并在 I/O 完成后重新调度 vCPU 继续执行。

5 虚拟机管理

5.1 virtio 半虚拟化驱动

5.1.1 virtio 的工作原理

virtio是半虚拟化 I/O 框架，客户机通过前端驱动与 QEMU 后端通信，绕过完整设备模拟，大幅减少 VM-Exit，提升网络和磁盘性能。相比模拟的 e1000 网卡或 IDE 磁盘，virtio 可提升 2-5 倍 的吞吐量。

5.1.2 virtio 设备类型

包含 virtio-net、virtio-blk、virtio-scsi、virtio-serial、virtio-rng 等。生产环境推荐全部使用 virtio 设备。

5.1.3 驱动获取

  • Linux：内核内置 virtio 驱动（需开启相关编译选项），主流发行版默认已启用
  • Windows：需下载对应版本的 virtio-win 驱动 ISO（Fedora 项目提供），安装系统时需加载驱动

5.2 libvirt 架构

libvirt 提供 API 统一管理 KVM、Xen、LXC 等。主要组件：

  • libvirtd：守护进程
  • virsh：命令行客户端
  • virt-manager：图形客户端
  • 网络、存储、节点设备管理

配置文件位置：

  • /etc/libvirt/：libvirt 主配置目录
  • /etc/libvirt/qemu/：虚拟机 XML 定义文件
  • /var/lib/libvirt/images/：默认磁盘镜像存储目录

5.3 virt-manager 管理

5.3.1 启动菜单

右键虚拟机可执行启动、暂停、关闭、迁移、快照管理、修改配置等操作。

5.3.2 远程管理 KVM 宿主机

通过 SSH 连接，添加连接 qemu+ssh://user@host/system，需对方开启 libvirt 远程访问权限。

5.3.3 性能监控

图形界面显示 CPU、内存、磁盘 I/O、网络流量实时图表。

5.3.4 管理快照

支持创建、恢复、删除快照（基于 qcow2 文件），方便回滚实验环境。

5.4 virsh 命令行工具

virsh 是核心管理命令，支持交互式和非交互式模式。

6 存储管理

6.1 KVM 存储模式

  • 文件存储：qcow2、raw、vmdk 等格式，存放在普通文件系统中
  • 块设备存储：LVM 逻辑卷、iSCSI、FC、本地磁盘分区
  • 网络存储：NFS、GlusterFS、Ceph RBD

推荐使用 qcow2 格式，支持稀疏文件、快照、压缩、加密。

7 网络管理（重点）

7.1 四种网络模式

KVM 支持四种网络模式：

模式 说明 类比 VMware
NAT 默认，虚拟机通过宿主机 NAT 访问外网 VMnet8
隔离（isolated） 仅虚拟机间通信，不与物理网络互通 仅主机（VMnet1）
桥接（bridge） 虚拟机与宿主机共享物理网卡，拥有独立 IP 桥接模式
直接分配（SR-IOV） 物理网卡直通，性能最高 —

虚拟机网卡类型支持 rtl8139、e1000、virtio-net-pci 等，生产环境强烈推荐 virtio。

7.2 宿主机 vnet 与虚拟机 eth0 的关系

这是前后端（backend/frontend）的非对称关系：

  • 虚拟机内的 eth0 是前端虚拟设备（virtio-net）
  • 宿主机上的 vnetX 是后端 TAP 接口（由 QEMU 创建）

7.3 默认 NAT 网络管理

安装 KVM 后自动创建一个名为 default 的 NAT 网络，其架构为：

  • 网桥：virbr0（IP 192.168.122.1）
  • DHCP/DNS：dnsmasq 服务，分配 192.168.122.2~254
  • NAT 转发：通过 iptables 规则实现

修改默认网络网段（如改为 10.0.0.0/24），使用 virsh net-edit default 编辑后重启网络。

方式 优点 缺点

libvirt 桥接网络 统一管理，virsh 可控制 物理网卡需支持混杂模式

7.5.3 跨主机通信方案

默认 NAT 网络无法跨主机通信。跨主机通信主要有三种方案：

  • 桥接网络：虚拟机获得与宿主机同网段的 IP，可直接被外部访问
  • VXLAN/Open vSwitch：在二层网络上叠加虚拟网络，实现跨主机二层互通
  • 路由方案：在宿主机上配置路由表，让不同宿主机的 NAT 子网互通

7.5.4 内外网隔离综合案例

场景：一台宿主机上存在多组虚拟机：

  • 内网组：仅宿主机内部通信（isolated），用于数据库集群
  • 外网组：桥接物理网卡（bridge），直接对外提供服务
  • 受限组：通过 NAT 访问外网但外部不可访问（nat），用于开发测试

实现方式：

  1. 创建三个 libvirt 网络：internal（isolated）、public（bridge）、dev（nat）
  2. 虚拟机按角色连接到对应的网络
  3. 利用 iptables/firewalld 控制不同网络间的访问规则

8 总结

本文从虚拟化基础概念出发，完整梳理了 KVM 技术栈的三大核心组件：

  • KVM：内核级硬件虚拟化加速器，负责 CPU 和内存虚拟化
  • QEMU：用户态设备模拟器，负责 I/O 设备模拟，每个虚拟机对应一个进程
  • libvirt：上层管理接口，提供 virsh、virt-manager 等工具，统一管理虚拟机生命周期

三者分工明确、协同工作，构成了 Linux 平台上最主流的开源虚拟化方案。通过本文的实践指导，从环境部署到虚拟机创建，再到网络精细配置，读者应能在 Ubuntu 系统上独立搭建并管理 KVM 虚拟化环境。

关键要点回顾：

  • CPU 必须支持硬件虚拟化（vmx/svm 标志）
  • 生产环境虚拟机磁盘使用 qcow2 格式，网卡使用 virtio 驱动
  • NAT 网络适合单机实验，桥接网络适合生产服务
  • virsh 是日常管理的最核心命令，建议熟练使用
